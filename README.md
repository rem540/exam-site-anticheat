# 在线限时答题系统（防作弊版）

一个纯前端的**在线限时答题 / 线上笔试**系统：考生从名单里搜出自己的身份进入考场，全程计时、带个人水印、禁复制并记录作弊信号，交卷后答案写入云端数据库；管理员在另一个页面评卷、打分、导出 CSV，并能重置身份或限定入场时间。

最初是为一次部门内推面试而写的，现整理成开源版本。

> 本仓库里的**名单和题目全部是占位示例**（`测试01`…`测试51`、示例题），云端配置也是占位符。请替换成你自己的内容后再部署。

---

## 功能

**考生端（`index.html`）**

- **搜索式身份选择**：输入姓名或班级实时过滤名单，选中后折叠成一条身份标签；已被别人选过的身份自动置灰并标注「已被选择」。
- **每个身份只能作答一次**：在数据库层面用部分唯一索引强制保证，同一身份同时只允许一条有效记录。答完要重考，需管理员在后台重置。
- **限定入场时间**：管理员设定开放/截止时间，不在时间窗内无法点「开始答题」，页面会显示倒计时或截止提示。**已开考的考生不受截止时间影响**，仍可正常答完交卷。
- **60 分钟倒计时**：计时基准取自服务器时间 + 浏览器单调时钟，刷新页面、关掉重开、修改系统时间都不会延长或重置。
- **断点续答**：答案每 30 秒自动暂存到云端，误关页面后可继续；本地也留一份草稿。
- **到点自动交卷并锁定**，也可提前手动交卷（二次确认）。交卷后服务端写死不可改。
- **全页水印**：姓名 + 班级 + 日期时间平铺整页，导出 PDF 时也带水印。
- **防作弊**：禁右键、禁复制、禁粘贴、禁拖拽，拦截 F12 与常用开发者工具快捷键；切屏、开调试器、尝试粘贴/复制/右键的**次数会被记录并随答卷一起提交**。
- 答完可导出 PDF 自留一份。

**管理端（`admin.html`）**

- 口令进入；首页看板统计：已进入答题 / 已交卷 / 答题中 / 超时交卷 / 已评分 / 已重置。
- 列表按姓名班级排序，点任意一行查看该考生完整答卷并逐题打分（自动累加总分）。
- **导出全站 CSV**（含每题答案与得分，Excel 直接打开），也可复制单份答卷的 CSV。
- **重置身份**：单个重置或一键全部重置，释放后该考生可重新答题（旧记录保留并标记「已重置」）。
- **限定入场时间**：设置开放/截止时间，或清除（不限时）。
- 删除记录。

## 目录结构

```
.
├── index.html            # 考生答题页（身份选择 / 计时 / 水印 / 防作弊 / 交卷）
├── admin.html            # 管理评卷后台
├── sql/
│   └── schema.sql        # 数据库表结构 + 全部 RPC 函数（部署时执行一次）
├── tools/
│   └── set-roster.py     # 用 roster.txt 批量替换两个页面里的名单
├── roster.example.txt    # 名单示例（每行「班级-姓名」）
└── LICENSE
```

整个前端就是两个静态 HTML 文件，没有构建步骤、没有依赖包，丢到任何静态托管上就能跑。

## 快速开始

### 1. 准备一个后端

前端需要三样东西：一个数据库、一组 RPC 接口、一个可用的 SDK 入口。参考实现用的是推理平台自带的**云服务**（托管 PostgreSQL + PostgREST 风格 RPC + 浏览器 SDK）。

**推荐路径**：在支持云端一键开应用的平台里创建一个应用，拿到它的 `endpoint` 与 `publishableKey`，然后用 `sql/schema.sql` 初始化数据库。

**自建路径**：起一个 PostgreSQL，把 `sql/schema.sql` 里的 `CHANGE_ME_ADMIN_TOKEN` 换成你自己的口令后执行；再在其前面搭一层 PostgREST（或任意能把 `POST /rpc/<函数名>` 转到 Postgres 函数的服务）。此时需要自行实现 SDK 里 `database.rpc(name, params)` 的等价物。

### 2. 初始化数据库

在数据库里执行 `sql/schema.sql`。它会建两张表（`exam_submissions`、`exam_settings`）、开启 RLS（不建策略，匿名角色无法直接读写表）、并创建所有函数。

> 函数是 `SECURITY DEFINER` 的，所以前端即使没有表权限，也能通过它们完成读写。**别忘了把 `CHANGE_ME_ADMIN_TOKEN` 换成自己的口令。**

### 3. 填入配置

两个 HTML 文件的 `<script>` 开头都有一段 `CLOUD` 配置，把它改成你自己的：

```js
var CLOUD = {
  endpoint: 'https://YOUR-ENDPOINT.example.com',
  publishableKey: 'wbpk_YOUR_APP_ID_YOUR_PUBLISHABLE_KEY',
  oauthRelayBaseUrl: 'https://YOUR-OAUTH-RELAY-URL'
};
```

同时把 `sql/schema.sql` 里的口令、以及 `admin.html` 中调用管理端函数时传入的 `p_token` 保持一致。

### 4. 换成你自己的名单

编辑 `roster.example.txt`（每行一个 `班级-姓名`），然后：

```bash
python tools/set-roster.py roster.example.txt
```

脚本会同时更新 `index.html` 与 `admin.html` 里的 `ROSTER` 数组。

### 5. 换成你自己的题目

题目在 `index.html` 里，位于 `<script type="text/template" id="paperTpl">` 与它对应的 `</script>` 之间，就是一段普通的 HTML。

题面里有两个必须保留的挂钩，否则初始化脚本会报错：

- `#cmdTable`（表格）与 `#btnAddCmd`（加行按钮）—— 用于「多行命令/对照」类题目；
- `#btnSortClear` —— 排序题的清空按钮。

其余都是可选的，可以自由增删：

| 结构 | 用途 |
| --- | --- |
| `input/textarea/select` 上的 `data-k="..."` | 答案字段名，收卷时按这个 key 收集 |
| `<select class="blank">` | 会被自动填入 `ROLES` 里的岗位选项 |
| `<span class="choice" data-k="...">` + 两个 `<button data-v="yes/no">` | 判断题（对/错） |
| `.sorter` 下的 `select.sort-sel`、`#sortOut` | 排序题 |
| `#q7c` | 字数统计显示位 |
| `textarea.ans` | 自动撑高的答题框，加 `tall` 更高 |

改完题目后，记得同步修改 `admin.html` 里的 `QUESTIONS`（评卷页的题目标签与字段分组）和 `MAXES`（各题满分），否则评卷界面对不上。

### 6. 发布

两个 HTML 是纯静态文件，丢到任意静态托管 / 对象存储 / CDN 即可。**只把 `index.html` 的地址发给考生**，`admin.html` 自己留着。

## 安全说明

- **匿名角色无法直接读写表**。两张表都开了 RLS 且没有策略，前端只能通过 `SECURITY DEFINER` 函数访问，因此考生拿不到别人的答卷。
- **管理端靠口令**。`admin_*` 系列函数都校验 `p_token`，口令写在前端请求里。这不是强认证，只适合内部小范围使用；如果口令泄露，拿到的人可以看到全部答卷。要更严格的话，建议换成真正的账号体系（把 `admin_*` 函数改成校验登录用户，而不是裸 token）。
- **防作弊是「提高成本」而不是「杜绝」**。前端的禁止复制/检测开发者工具都能被绕过，作弊信号也只是提示性记录。真要严格考试，请配合线下监考或专门的考试系统。
- **题面是内联在页面里的**。开考前面板被盖住且禁用了开发者工具，但理论上查看网页源码仍能提前看到题目。若要更强，可改为「开考建立会话后才从服务端下发题面」。
- **不要把真实名单、真题和口令提交到公开仓库。**

## 已知取舍

- 计时以服务端 `started_at` 为准，答案是每 30 秒增量上传；若考生在最后 30 秒内断网，最后几秒的输入可能丢失（交卷时会立即上传一次，正常情况下不会丢）。
- 答案整体存在一个 `jsonb` 字段里，便于题目变化，但不利于按题目做统计查询。需要统计时导 CSV 处理即可。
- 「重置身份」不删除记录，只写入 `released_at`，因此同一身份可能有多条历史记录（旧记录标记为「已重置」）。想彻底清掉请用删除。
